# Project structure

```
src/
├─ app/                        Expo Router routes — one-line re-exports
│  ├─ _layout.tsx              root Stack and every provider
│  ├─ index.tsx                the only screen
│  ├─ +html.tsx                web document shell
│  └─ [...messing].tsx         404
├─ features/
│  └─ home/
│     ├─ home-screen.tsx
│     ├─ home-screen.test.tsx
│     └─ components/
│        ├─ preferences-bar.tsx
│        ├─ toggle-preferences.ts
│        └─ toggle-preferences.test.ts
├─ components/ui/              design system
│  ├─ colors.js                palette consumed by the navigation theme
│  ├─ focus-aware-status-bar.tsx
│  ├─ text.tsx                 Text with the `tx` translation prop
│  ├─ use-theme-config.tsx     maps the Uniwind theme to a navigation theme
│  └─ index.tsx                barrel, plus React Native re-exports
├─ lib/
│  ├─ api/                     axios client, query provider, pagination helpers
│  ├─ hooks/                   use-selected-theme
│  ├─ i18n/                    i18next setup, typed keys, locale resources
│  ├─ storage.tsx              MMKV wrapper
│  ├─ test-utils.tsx           render with providers
│  └─ utils.ts                 createSelectors for Zustand stores
├─ translations/               en-us.json, pt-br.json
└─ global.css                  Tailwind theme tokens
```

## What goes where

**`src/app/`** — nothing but re-exports and layouts. If a file here has a hook in it, it is in the wrong place. The one exception is `_layout.tsx`, which owns the provider tree.

**`src/features/<name>/`** — one folder per domain. A feature holds:

| File | When |
| --- | --- |
| `<name>-screen.tsx` | always — the screen the route re-exports |
| `components/` | components used only by this feature |
| `api.ts` | this feature's queries and mutations |
| `use-<name>-store.tsx` | this feature's Zustand store |
| `*.test.ts(x)` | beside the file under test |

Only `components/` is allowed as a subfolder. Use single files (`api.ts`), not folders (`api/`), until a file genuinely outgrows itself.

**`src/components/ui/`** — reusable and domain-free. If it mentions a business concept, it belongs to a feature.

**`src/lib/`** — infrastructure with no UI and no domain. Anything here should be understandable without knowing what the app does.

## Root files

| File | Purpose |
| --- | --- |
| `app.config.ts` | Expo config. Config plugins go here, never in `ios/` or `android/` |
| `env.ts` | environment schema, validated with Zod, and the per-environment bundle ids |
| `metro.config.js` | Metro plus the Uniwind transformer |
| `eslint.config.mjs` | lint *and* formatting — there is no Prettier |
| `jest-setup.ts` | global mocks for native modules |
| `uniwind-types.d.ts` | generated by Uniwind on every Metro run; ESLint-ignored on purpose |

`ios/` and `android/` are generated by `pnpm prebuild` and are git-ignored. Never edit them: the next prebuild overwrites your changes. Native configuration belongs in `app.config.ts` as a config plugin.
